# AW — Accounting authority and temporal-control design (proposal; non-executable)
## 1. Ownership and boundaries
Accounting Core owns immutable posted journals, postings, accounting periods and balances derived from journals. Regulatory Authority owns effective-dated legal instrument provenance and status. Chart Authority owns versioned PCEC mapping candidates and institution approvals. Credit Risk owns classification decisions and supporting evidence; it **cannot directly change GL balances**. Payments/Settlement own external state evidence, not posting authorization.
## 2. Chart release entity (proposed)
`ChartRelease{release_id,institution_id,regulatory_profile,source_instruments[],effective_from,effective_to,approved_at,approved_by,second_approver,source_hashes[],mapping_version,status}`. State: DRAFT -> EVIDENCE_REVIEW -> CFO_APPROVED -> COMPLIANCE_APPROVED -> SCHEDULED -> ACTIVE -> RETIRED; any disputed legal effect -> QUARANTINED. Distinguish legally effective date, approval timestamp, operational activation timestamp and business event date. Enforce no overlapping ACTIVE chart for same institution/profile and effective interval; preserve all historical mappings.
`AccountMapping{chart_release_id,source_code,internal_account_id,financial_statement_bucket,off_balance_flag,dimensions_required[],mapping_provenance,approved_status}`. Unknown code => fail closed to suspense/exception workflow with controlled resolution, not an invented destination account.
## 3. Journal invariants
Posted journals immutable; exact monetary arithmetic; each journal balanced by currency and permitted ledger dimension; class 9 off-balance entries have their own double-entry balancing control (PCEC historical text pp.16–17); derived class-8 management indicators are not ordinary money-creating entries; no direct customer balance mutation. Posting requires maker-checker where policy dictates, durable idempotency key, source document and audit correlation ID. FX conversion uses independently recorded exchange rates and approved gain/loss entries; never silently net assets/liabilities.
## 4. Day closure and historical correction
The 1998 PCEC instructs same-day booking and no post-close entries except exceptional complementary days. Proposed `AccountingPeriod` states OPEN -> CLOSING -> CLOSED -> SEALED, with separately authorized `COMPLEMENTARY_WINDOW` only if institution/regulatory policy approves. A closed period cannot accept ordinary backdated posting. Prior-period errors use dated correction/reversal journals and explicit restatement/reporting procedure where authorized; do not mutate historical posted rows or silently alter the original chart snapshot. Preserve report 'as originally filed' and 'restated' versions.
## 5. Evidence-to-report lineage
Every financial statement cell must trace to source documents -> business event -> posting intent -> approved mapping version -> journal lines -> aggregation -> report cell, with reversible drill-down. PCEC Annex I requires dimensions such as counterparty residence and group attributes; record provenance and effective dating rather than guessing absent attributes. Source identity, retention and privacy need current legal review.
## 6. Credit classification and provision posting
R-2018/01 credit classifications are **risk states**, not direct ledger mutations. Proposed flow: risk assessment -> evidence/eligibility checks -> approved classification -> provision calculation proposal -> maker-checker -> accounting posting via Accounting Core -> reconciliation. Collateral affects provisioning where permitted, not initial classification. No rate/threshold is executable until current legal source and institution profile are signed off.
## 7. Operational failure and security
Transactional outbox/inbox, idempotent replay, independent reconciler, unknown-external-outcome quarantine, tamper-evident audit, least privilege, key custody, DR restore tests and business-date rollover testing. Prevent a status update from creating or destroying money. Manual overrides require dual control, reason, expiry and evidence. All unresolved legal or mapping gaps => no financial activation.
## 8. Migration safeguards
Historical PCEC code import is **reference-only** until reconciled with I-2002/01, I-2003/01, I-2015/01, R-2018/01 and any newer official amendments. Migration must validate trial balances, opening=prior closing, on/off-balance separation, report reconstruction and zero unexplained differences. The 1998 Cameroon year-end statement is historical; never hard-code it into the 2026 calendar.
